1. ARCHITECTURE OVERVIEW & PORT ALLOCATIONS
--------------------------------------------------------------------------------
The platform is designed as an event-driven, microservices-based application. 
All backends share the same JWT signature key and connect directly to the native 
Windows host MongoDB instance via 'host.docker.internal'.

- React Frontend:         Port 5173 (Served via Vite in dev / Nginx in container)
- Auth Service:           Port 8001 (User registration, login, profile, and JWT generation)
- Project Service:        Port 8002 (Project CRUD, dynamic Risk Engine, Auto Timeline)
- Feedback Service:       Port 8003 (Citizen complaints with location, severity, & photo)
- Document Service:       Port 8004 (Static file server, file upload with incremental versioning)
- Analytics Service:      Port 8005 (Monthly trends, budget burn-rates, and department success rankings)
- Notification Service:   Port 8006 (WebSockets push server for real-time dashboard notifications)
- Audit Service:          Port 8007 (Audit feed database logging administrative actions)
- AI Prediction Service:  Port 8008 (AI delay predictions, NLP project summaries, text categorizer)
- Database:               Windows MongoDB (Host port 27017)
- Prometheus Scraper:     Port 9090 (FastAPI prometheus-instrumentator metrics collector)
- Grafana Dashboards:     Port 3000 (Scraped service health and latency visualizations)

2. BACKEND MICROSERVICES ARCHITECTURE & SCHEMAS
--------------------------------------------------------------------------------

A. Auth Service (Port 8001)
   - Handles account creations, credentials validation, and role-based profiles.
   - Core Hashing: Employs direct 'bcrypt' hashing (avoiding passlib compatibility issues).
   - JWT Claims Upgrades: Embeds user 'name', 'email', and 'district' metadata in the 
     token claims, allowing downstream services to decrypt tokens locally.
   - Endpoints:
     - POST `/api/v1/auth/register` (creates user record with district selection)
     - POST `/api/v1/auth/login` (generates JWT token with name, email, role, district claims)
     - GET `/api/v1/auth/profile` (returns active authenticated user profile details)

B. Project Service (Port 8002)
   - Performs CRUD operations. Evaluates user permissions using token claims.
   - District boundary filters: If the token role is 'Citizen' or 'Engineer', all project 
     listings default to and strictly validate against their registered district.
   - Project Risk Engine:
     - Automatically calculates a dynamic risk score (0-100) and assigns a risk badge.
     - Adds score weight based on project deadline overruns, total complaints, and budget size.
     - Outputs: Low (<35, Green 🟢), Medium (35-70, Yellow 🟡), and High (>=70, Red 🔴).
   - Auto Timeline Event Generator:
     - Instantly injects chronological timeline milestones when:
       * Project is created (Sanctions milestone).
       * Construction begins (Status changes to 'In Progress').
       * Reaches 20% or 50% completion checkpoints.
       * Official inspection is booked (Status changes to 'Inspection Scheduled').
       * Project finishes (Status changes to 'Completed').
       * Project falls behind (Status changes to 'Delayed').
       * Assigned engineer is updated.
   - Endpoints:
     - GET/POST `/api/v1/projects` (creates project, restricts list/creation by role/district)
     - GET/PUT/DELETE `/api/v1/projects/{id}` (manages project details, checks district bounds)
     - GET/POST `/api/v1/projects/{id}/timeline` (milestone logs with photo attachments)

C. Feedback Service (Port 8003)
   - Manages public grievances, suggestions, and complaint workflows.
   - Upgraded Schema: Includes 'location' text, 'severity' levels (Low/Medium/High), and 
     'image_url' for visual proof.
   - Security Boundary: Citizens and Engineers cannot view or submit complaints for 
     projects outside their registered district.
   - Activity Logging: Directly posts a notification log to the global audit feed when 
     a citizen files a new complaint.
   - Endpoints:
     - GET/POST `/api/v1/feedback` (submits and lists complaints based on district locks)
     - PUT `/api/v1/feedback/{id}` (updates complaint status: OPEN, ASSIGNED, RESOLVED)

D. Document Service (Port 8004)
   - Hosts uploaded construction drone shots, project contracts, and layouts.
   - Static Files Mount: Configures FastAPI middleware to serve files from `static/uploads`.
   - File Versioning System:
     - Checks if a file with the same project ID and filename exists in MongoDB.
     - If detected, keeps the original file and increments the suffix on disk (e.g. `_v2`, `_v3`) 
       to preserve historical uploads in a version timeline.
   - District Security: Restricts uploads and listings to the user's district for citizens/engineers.
   - Endpoints:
     - POST `/api/v1/documents/upload` (accepts file uploads, handles versions, logs activity)
     - GET `/api/v1/documents/project/{project_id}` (retrieves version history for details page)

E. Analytics Service (Port 8005)
   - Aggregates multi-service database records for high-fidelity frontend graphs.
   - Endpoints:
     - GET `/api/v1/analytics/trends` (computes monthly spending trends in INR)
     - GET `/api/v1/analytics/burn-rate` (computes cumulative spending burn-rate)
     - GET `/api/v1/analytics/forecast` (calculates estimated remaining days for completion)
     - GET `/api/v1/analytics/complaints` (distributes complaints by location and severity)
     - GET `/api/v1/analytics/rankings` (ranks departments by success/timely completion rates)

F. Notification Service (Port 8006)
   - Handles real-time communication between active users and backend updates.
   - Connection Manager: Manages open WebSocket connections under `/ws/{user_email}`.
   - Broadcast System: When services publish updates to `/api/v1/notifications`, the service 
     instantly routes live JSON payloads to active user sockets to display visual toast popups.
   - Endpoints:
     - GET/POST `/api/v1/notifications` (manages database notifications logs)
     - WS `/ws/{user_email}` (live WebSocket connection endpoint)

G. Audit Service (Port 8007)
   - Serves as the central logging service for administrative activities.
   - Endpoints:
     - GET/POST `/api/v1/audit/activities` (logs platform-wide actions like user log-ins,
       complaint submissions, file uploads, and project status modifications)

H. AI Prediction Service (Port 8008)
   - Machine Learning prediction helper using in-memory model simulators.
   - Endpoints:
     - POST `/api/v1/prediction/delay` (regression estimates for project delays)
     - POST `/api/v1/prediction/categorize-complaint` (rules-based NLP complaints classifier)
     - POST `/api/v1/prediction/summarize-project` (generates natural language summaries of status)

4. INFRASTRUCTURE & MONITORING DEFINITIONS
--------------------------------------------------------------------------------

A. Docker Compose (docker-compose.yml)
   - Builds 9 local containers (8 backend services + 1 frontend).
   - Resolves host communication via `host.docker.internal` pointing directly to your 
     Windows host's native MongoDB service.
   - Configures `extra_hosts` to ensure the host IP maps reliably inside all container environments.
   - Mounts static folders to store document files persistently on disk.

B. Prometheus Scraper Configuration (docker/prometheus/prometheus.yml)
   - Configures standard jobs to scrape HTTP performance metrics from FastAPI's 
     `prometheus-fastapi-instrumentator` on ports 8001–8003.

C. Grafana Dashboard Configuration
   - Runs on port 3000 to visualize metrics compiled from the Prometheus collector.

--------------------------------------------------------------------------------
5. SEEDING & DATABASE MANAGEMENT
--------------------------------------------------------------------------------
The database seeder script `scripts/seed_large_db.py` completely handles the initial state:
1. **Purges all old data:** Deletes `users`, `projects`, `timeline`, `feedback`, `activities`, 
   `documents`, `notifications`, and `audit_logs` collections.
2. **Generates projects:** Injects 760 projects (20 for each of the 38 TN districts).
3. **Creates district users:** Programmatically registers a Citizen and an Engineer for 
   all 38 districts (e.g. `citizen.salem@example.com` and `engineer.salem@gov.in`), along with 
   Chief Officer (`officer@example.com`) and System Admin (`admin@example.com`), hashing their 
   passwords with `bcrypt` (password: `TempPass!23`).
