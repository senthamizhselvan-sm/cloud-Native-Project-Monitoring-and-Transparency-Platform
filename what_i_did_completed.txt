PART 2: PHASE 1 — FEEDBACK SERVICE (GOVERNMENT WORKFLOW)
------------------------------------------------------------------------
Created a new, independent microservice under `services/feedback-service/` 
running on port `8003` to manage citizen grievances.

- Backend Architecture:
  - `requirements.txt`: Standard backend packages (FastAPI, Motor, Uvicorn, Jose).
  - `app/core/config.py`: Environment configurations loader.
  - `app/core/security.py`: JWT decoder validating against shared secret.
  - `app/db/mongodb.py`: Async Motor MongoDB driver connection setup.
  - `app/models/feedback.py`: Database schema representing feedback items.
  - `app/schemas/feedback.py`: Pydantic input validation structures.
  - `app/repositories/feedback_repository.py`: Async MongoDB queries.
  - `app/services/feedback_service.py`: Business logic layer.
  - `app/api/v1/routes/feedback.py`: API routes endpoints:
    - POST `/api/v1/feedback`: Creates a complaint. Automatically reads 
      `citizen_id` from JWT sub payload.
    - GET `/api/v1/feedback`: Lists own complaints (for Citizens) or all 
      complaints (for Officers/Admins).
    - PUT `/api/v1/feedback/{id}`: Updates status and assigns inspector (restricted).
- Frontend Views & Wiring:
  - `CitizenDashboard.tsx`: Displays a list of issues submitted by the logged-in 
    citizen and links to the reporting form.
  - `FeedbackForm.tsx`: Fetches active projects from project-service and 
    submits complaints to feedback-service.
  - `FeedbackManagement.tsx`: Allows Officers to view all citizen reports, 
    input inspector names, and mark reports as resolved. Maps project IDs to 
    names in-memory.
  - `Sidebar.tsx`: Added dynamic links for feedback dashboards.
